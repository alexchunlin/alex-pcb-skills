# Survey: AI-agent and code-driven PCB design, tooling and benchmarks (2026-10-31)

Run for the game plan (`docs/GAMEPLAN.md`). Four sub-surveys by research agents under a fetch-and-cite rule; every
claim carries the URL it was read from. Target: KiCad 10 on macOS, headless. Items that could not be verified say so.

Sections: 1 code-as-schematic and file libraries; 2 MCP servers and agent integrations; 3 autorouters and placers;
4 checks beyond ERC/DRC; 5 benchmarks and papers; 6 datasets; 7 sourcing APIs and footprint import.

---

## 3. Autorouters and placement engines (headless)

- **freerouting v2.5.0** (2026-10-05): GPL-3, 2,160 stars; GraalVM native binaries for macOS arm64/x64 (no JRE);
  CLI `-de board.dsn -do board.ses -mp N -mt N -drc report.json --gui.enabled=false --router.copperToEdgeClearanceUm`;
  Docker `ghcr.io/freerouting/freerouting` (amd64, arm64); REST API v1 (`POST /v1/autoroute`, DSN in, SES/KICAD_JSON/
  DRC_JSON out); MCP server (`autoroute_board`, session/job tools; offline via `--mcp_server.stdio=true`); Python
  client. Benchmark: 1,157 boards, 75.0% clean, 75.4% fully routed, 6.7% timeouts; tier A 452/453, tier C 49%. Known
  KiCad DSN gaps: edge clearance not exported, pad enlargement, per-layer widths, keepouts, SES via drills (Oct 2026
  issues). Maintainer ~4 h/week. https://github.com/freerouting/freerouting/releases/tag/v2.5.0 ,
  docs/command_line_arguments.md , docs/API/API_v1.md , docs/API/MCP.md
- **KiCad built-in**: no autorouter in 10; issue #25885 (2026-10-21) offered a C++ port of freerouting and was closed
  the same day: the codebase "remains in copyright dispute". Auto-placer is the ratsnest-length heuristic; crossing-
  minimization MR !2326 open since 2025-10-12. https://gitlab.com/kicad/code/kicad/-/issues/25885 ,
  https://gitlab.com/kicad/code/kicad/-/merge_requests/2326
- **KiCadRoutingTools** (drandyhaas; atomic14 fork): Rust-accelerated A*, reads/writes `.kicad_pcb` directly, KiCad 9

  skills, PCM plugin; no push-and-shove, no global planning; used as the "KRT" baseline in PCBWorld. 724 stars, MIT,
  v0.23.7 (2026-10-23). https://github.com/drandyhaas/KiCadRoutingTools , https://github.com/atomic14/KiCadRoutingTools
- **rjwalters/kicad-tools (`kct`)**: `kct placement`, `optimize-placement` (CMA-ES/Bayesian), `route`, `route-auto`,

### 5.4 Gaps the literature leaves

1. No public runnable benchmark for spec to KiCad schematic + PCB with ERC + DRC + fab rules.
2. No benchmark applies fab DFM rules; all use generic DRC.
3. KiCad-format layout data is thin (PCBWorld's 679 boards, routing only).
4. No benchmark scores placement, routing and electrical function on one board from one prompt with a public leaderboard.
5. No benchmark for schematic-to-layout consistency after agent edits.
6. LLM-as-judge for schematics does not agree with humans (MultModLM); CircuitLM and PCB Gym still use judges.
7. Vision on schematics is far from usable (OmniSch).

## 7. Sourcing APIs and footprint import

- **LCSC official API**: REST (`product/v1/keywordsearch`, `productdetails`, `productchangenotifications`), approval-gated
  (apply, review, sandbox key first, production second), IP whitelist, HMAC signature with 60 s nonce window; search
  quota 60/min and 1000/day; list prices only. https://www.lcsc.com/agent , https://www.lcsc.com/agent/basic-rules ,
  https://help.luminovo.com/en/articles/148501-lcsc
- **JLCPCB Components API** ("JLCAPI", api.jlcpcb.com): "apply for free API access"; docs JS-rendered. Endpoints seen in
  yaqwsx/jlcparts' fetcher: `open.jlcpcb.com/overseas/openapi/component/getComponentLibraryList` and
  `getComponentDetailByCode` with `JOP appid=...,accesskey=...` HMAC headers. https://api.jlcpcb.com/ ,
